# dedup：企业数据清洗模糊查重库

Go 实现的进程内模糊查重组件，供上层数据清洗任务调用。针对"名称、地址存在错字"
的重复客户记录，完整找出值得人工复核的记录对并组织成重复簇。本组件只做检测，
不修改原始记录，也不负责人工合并。

## 功能

- 对两条记录评分（`ScorePair`），或对整批记录查重（`FindDuplicates`）。
- 批次查重返回：全部达标记录对（含各对综合分数）与重复簇。
- 同一 ID 不与自身比较，同一对记录只返回一次；孤立记录不进入重复簇。
- 结果与输入顺序无关：候选对按 `(ID1, ID2)` 升序，簇内 ID 升序、簇间按首个 ID 升序。

## 评分规则

- 单字段使用按 **Unicode 码点**（而非 UTF-8 字节）计算的 Levenshtein 编辑距离，
  插入、删除、替换代价均为 1。
- 字段相似度 = `(1 - 编辑距离 / 较长字段长度) × 100`；两字段均空时约定为 100。
- 综合分数 = 名称相似度与地址相似度的算术平均值，默认阈值 **85**（可用
  `FindDuplicatesWithThreshold` 调整）。
- 判定使用未舍入的数学值：整数阈值下用整数有理数比较，
  综合分数恰好 85 的记录对必然命中。
- 综合达标只要求两列平均值达标，不要求任何一列完全相等，
  也不要求两列各自都达到 85。

## 使用示例

```go
import "dedup"

records := []dedup.Record{
    {ID: "c001", Name: "北京朝阳创新科技发展有限公司", Address: "北京市朝阳区建国路88号"},
    {ID: "c002", Name: "北京朝阳创新科技发展有限公司", Address: "北京市朝阳区建国路88号院"},
    {ID: "c003", Name: "上海浦东贸易有限公司", Address: "上海市浦东新区世纪大道100号"},
}

res := dedup.FindDuplicates(records) // 等价于 FindDuplicatesWithThreshold(records, 85)
for _, p := range res.Pairs {
    fmt.Printf("%s ~ %s  score=%.2f (name=%.2f addr=%.2f)\n",
        p.ID1, p.ID2, p.Score, p.NameSimilarity, p.AddressSimilarity)
}
for _, cluster := range res.Clusters {
    fmt.Println("重复簇:", cluster)
}

// 单对评分
pair := dedup.ScorePair(records[0], records[1])
```

## 算法与完备性

直接逐对比较 10000 条记录需要约 5000 万对评分，代价过高。本库采用
**过滤—验证** 框架，保证结果与逐对精确评分完全一致：

1. **鸽笼分路**：综合分数 ≥ T 蕴含名称或地址至少一列相似度 ≥ T。
   名称趟输出名称达标的对，地址趟输出名称不达标（因而地址必达标）的对，
   两趟互不重叠、并集完备。
2. **前缀过滤生成候选**：每趟在单字段上按 bigram 计数过滤
   （编辑距离为 d 时两字段至少共享 `max(|A|,|B|) - 2d` 个 bigram），
   用按全局稀有度排序的前缀索引（ppjoin 风格）枚举所有可能达标的记录对，
   流式回调、不物化候选集。
3. **精确验证**：候选对依次经过长度过滤、bigram 计数过滤、
   带状有界 Levenshtein（距离超过上界即提前终止），
   最后用整数有理数判定综合分数是否达标。
4. **重复簇**：对达标记录对做并查集连通分量，间接相连的记录同属一簇；
   簇内不虚构未达标的记录对。

所有过滤条件都是编辑距离上界的**必要条件**，因此不会漏掉任何达标对；
不达标对也不会进入结果。

## 复杂度

- 单条记录评分：O(L²)，L 为字段长度（≤ 60 码点时约 3600 次操作）。
- 整批查重：候选生成与验证均随"真实相似对"数量线性增长；
  有界 Levenshtein 每对代价 O(d·L)，d 为允许的最大编辑距离。
- 内存：索引与结果均为 O(n + 达标对数)，全部在进程内存中。

## 性能（可复现）

环境：Apple Silicon（arm64），Go 1.27，10000 条记录、字段 20–60 码点。
运行 `go test -run TestPerf -v` 可复现：

| 场景 | 数据特征 | 达标对 | 耗时 | 结果驻留堆内存 | 累计分配 |
|---|---|---|---|---|---|
| 同名地址分散 | 50 个 100 人同名大组 + 1000 个 5 人小组，地址随机分散，植入 500 对达标对 | 500 | ≈0.51 s | 0.3 MiB | 171 MiB |
| 双字段错字 | 1000 个实体 × 10 条变体，名称地址各带 1–2 处错字 | 45000 | ≈0.48 s | 2.9 MiB | 159 MiB |

均远低于 20 s / 256 MiB 的预算。同名场景下名称趟会产生约 26 万次候选验证，
靠 bigram 计数过滤与有界距离在毫次级完成；错字场景输出 45000 个达标对，
接近 50000 对的设计上限。

## 假设与边界

- 输入 ID 唯一；名称、地址非空且已由上游完成大小写与空白标准化，
  本组件直接比较收到的文本。
- 单批处理，不支持增量更新；`FindDuplicates` 内部无共享状态，
  不同批次可在不同 goroutine 中并发调用。
- 自定义阈值取 (0, 100]；默认 85。
